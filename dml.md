# DML (INSERT / UPDATE / DELETE / MERGE)

> **Baseline:** SQL Server **2025** (17.x) · PostgreSQL **19**.  
> DML đổi dữ liệu trong **transaction**. Cùng cú pháp `UPDATE … FROM` trên hai engine **không** cùng ngữ nghĩa khi một hàng khớp nhiều nguồn — đây là nguồn corruption im lặng trên PostgreSQL.

`INSERT`/`UPDATE`/`DELETE`/`MERGE` là đơn vị atomic *theo statement* trong autocommit, hoặc một phần txn tường minh. SQL Server mặc định lỗi một statement **không** abort cả txn (`XACT_ABORT OFF`); PostgreSQL lỗi → abort txn trừ savepoint. Isolation, `FOR UPDATE`, leftover temporal: [transactions.md](transactions.md), [concurrency.md](concurrency.md). Trigger: [routines.md](routines.md). Constraint lúc ghi: [constraints.md](constraints.md).

PostgreSQL 19 **beta**: `ON CONFLICT DO SELECT`, `FOR PORTION OF`, SIMD `COPY` (`ON_ERROR SET_NULL`, `FORCE_ARRAY`, cấm system column). SQL Server Change Event Streaming = **PREVIEW** — khác `TRUNCATE`/CDC.

## 1. Tổng quan & triết lý

DML nên **hẹp, xác định, đo được số hàng**. `UPDATE`/`DELETE` không `WHERE` là xóa/ghi toàn bảng — luôn bọc txn và `SELECT` đếm trước trên production.

Ba chỗ lệch dialect:

- **Identity:** `IDENTITY` + `IDENTITY_INSERT` (SQL Server) vs `GENERATED … AS IDENTITY` + `OVERRIDING` (PostgreSQL).
- **Join khi ghi:** SQL Server `UPDATE t SET … FROM t JOIN …`; PostgreSQL `UPDATE t SET … FROM … WHERE` — fan-out **không xác định** nếu nhiều hàng nguồn.
- **Upsert:** `MERGE` (cả hai) vs `ON CONFLICT` (PostgreSQL, thường đơn giản hơn). `RETURNING OLD/NEW` (PG 18+) ≠ `OUTPUT inserted/deleted`. `DO SELECT` (**19**) = get-or-create không ghi đè.

Temporal application-time (`FOR PORTION OF`) **không** phải system-versioned SQL Server. Bulk không đi qua cùng trigger/log như từng hàng — đọc mục 7–9 trước khi “tối ưu”. CES **PREVIEW** stream DML, không thay `TRUNCATE` semantics.

## 2. INSERT, identity, OVERRIDING

```sql
INSERT INTO orders (customer_id, total)
VALUES (1, 99.50), (2, 10.00);

INSERT INTO orders (customer_id, total)
SELECT id, 0 FROM customers WHERE trial;

INSERT INTO orders DEFAULT VALUES;          -- mọi cột default / nullable
```

Liệt kê cột tường minh. `INSERT INTO t VALUES (…)` phụ thuộc thứ tự vật lý — vỡ khi `ALTER ADD`.

### 2.1 SQL Server IDENTITY

```sql
CREATE TABLE dbo.Orders (
    Id         int IDENTITY(1,1) NOT NULL PRIMARY KEY,
    CustomerId int NOT NULL
);

INSERT INTO dbo.Orders (CustomerId) VALUES (1);     -- Id do engine

SET IDENTITY_INSERT dbo.Orders ON;
INSERT INTO dbo.Orders (Id, CustomerId) VALUES (100, 1);
SET IDENTITY_INSERT dbo.Orders OFF;
```

Một bảng `IDENTITY_INSERT ON` mỗi session. `IDENTITY` có **lỗ** sau rollback / `SEQUENCE` cache — không dùng làm số hóa đơn liên tục.

### 2.2 PostgreSQL IDENTITY & OVERRIDING

```sql
CREATE TABLE orders (
    id          int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id int NOT NULL
);

INSERT INTO orders (customer_id) VALUES (1)
RETURNING id;

-- GENERATED ALWAYS: user không ghi id trừ khi
INSERT INTO orders (id, customer_id)
OVERRIDING SYSTEM VALUE
VALUES (100, 1);

-- GENERATED BY DEFAULT: user id được dùng; ép sequence:
INSERT INTO orders (id, customer_id)
OVERRIDING USER VALUE
VALUES (100, 1);            -- 100 bị bỏ, lấy nextval
```

`serial` / `bigserial` = `int` + sequence ẩn, **không** phải chuẩn identity — ưu tiên `GENERATED`. `setval` sau load bulk. Sequence **không** rollback — [ddl.md](ddl.md) §9.

`INSERT … SELECT` + unique: race với session khác → lỗi unique, không “tự skip” trừ `ON CONFLICT` / `MERGE`.

Cột generated (`VIRTUAL`/`STORED` / computed): không liệt kê trong `INSERT` (trừ identity `OVERRIDING`). `DEFAULT` cột thường: `INSERT … DEFAULT VALUES` hoặc `DEFAULT` tại chỗ. [ddl.md](ddl.md) §6.

```sql
INSERT INTO invoice (qty, price) VALUES (2, 10);  -- total generated
-- INSERT INTO invoice (qty, price, total) VALUES (2, 10, 20);  -- lỗi GENERATED ALWAYS
```

**Ghi chú:** SQL Server không dùng cú pháp `OVERRIDING SYSTEM VALUE`. Port dump: `IDENTITY_INSERT` hoặc `SEQUENCE` + `NEXT VALUE FOR` làm default. Trigger `INSTEAD OF INSERT` có thể nuốt identity — đọc [routines.md](routines.md).

## 3. UPDATE & fan-out PostgreSQL

**Hình dung.** Bạn bảo “đơn 7 lấy tổng từ bảng staging”. Staging có **hai** dòng `order_id = 7` (10 và 99). SQL Server `MERGE` thường **lỗi** “nhiều nguồn”. PostgreSQL `UPDATE … FROM` **không lỗi**: chọn **một** trong hai (plan quyết), ghi, im. Lần sau có thể số kia. Đừng đọc “chạy được” thành “đúng”.

Sửa: nguồn phải **một hàng / khóa** (`DISTINCT ON`, `GROUP BY`, subquery).

```sql
-- SQL Server
UPDATE o
SET o.total = o.total * 1.1
FROM dbo.Orders AS o
INNER JOIN dbo.Customers AS c ON c.Id = o.CustomerId
WHERE c.Country = N'VN';

-- PostgreSQL — không viết JOIN kiểu T-SQL
UPDATE orders AS o
SET total = total * 1.1
FROM customers AS c
WHERE c.id = o.customer_id
  AND c.country = 'VN';
```

PostgreSQL: `FROM` là tích với target qua `WHERE`. **Một hàng target khớp nhiều hàng `FROM` → cập nhật một lần, nguồn nào không xác định** (plan-dependent). Không báo lỗi. Đây là hazard khác `MERGE` (cardinality violation).

```sql
-- Nguy hiểm: staging trùng order_id
UPDATE orders AS o
SET total = s.total
FROM staging AS s
WHERE s.order_id = o.id;
-- o.total = một trong các s.total trùng khóa — không xác định
```

Ổn định: thu hẹp nguồn **một hàng / target**.

```sql
UPDATE orders AS o
SET total = s.total
FROM (
    SELECT DISTINCT ON (order_id) order_id, total
    FROM staging
    ORDER BY order_id, loaded_at DESC, id DESC
) AS s
WHERE s.order_id = o.id;
```

Hoặc subquery tương quan / `MERGE` (lỗi nếu nhiều nguồn). SQL Server `UPDATE … JOIN` nhiều khớp: cũng **không xác định** (last write), không phải an toàn hơn — `MERGE` thì lỗi 8672.

```sql
-- Portable: chỉ cột từ chính bảng
UPDATE orders
SET total = total * 1.1
WHERE customer_id IN (SELECT id FROM customers WHERE country = 'VN');
```

CTE `UPDATE` PostgreSQL: `WITH … UPDATE … FROM cte`. SQL Server: `WITH … UPDATE … FROM`.

**Ghi chú:** `SET col = col + 1` atomic hơn đọc-app-ghi. Lost update: [transactions.md](transactions.md) §6. `FROM` + `JOIN` phức tạp: luôn `SELECT` đếm `COUNT(*)` vs `COUNT(DISTINCT target_pk)` trước khi UPDATE.

## 4. DELETE theo lô

```sql
-- SQL Server
DELETE o
FROM dbo.Orders AS o
WHERE o.Status = N'cancelled';

-- PostgreSQL
DELETE FROM orders AS o
USING customers AS c
WHERE c.id = o.customer_id
  AND c.closed;
```

`USING`/`FROM` cùng hazard fan-out: một hàng xóa khớp nhiều nguồn — vẫn xóa một lần, nhưng `RETURNING`/`OUTPUT` và trigger “per join row” dễ hiểu nhầm. Thu hẹp nguồn.

Xóa lớn: **lô** để giới hạn lock, WAL, `xmin` / log truncation, timeout.

```sql
-- PostgreSQL: khóa lô qua ctid, tránh xóa lang thang
WITH batch AS (
    SELECT ctid
    FROM user_logs
    WHERE status = 'archived'
    ORDER BY created_at, id
    FOR UPDATE SKIP LOCKED
    LIMIT 10000
)
DELETE FROM user_logs AS u
USING batch AS b
WHERE u.ctid = b.ctid;
```

```sql
-- SQL Server
DELETE TOP (10000)
FROM dbo.UserLogs
WHERE Status = N'archived';
-- lặp đến @@ROWCOUNT = 0
```

`READPAST`/`SKIP LOCKED`: worker song song — [concurrency.md](concurrency.md). `ORDER BY` trong `DELETE TOP` SQL Server cần derived table / CTE (không `DELETE TOP … ORDER BY` trực tiếp trên mọi phiên bản theo nghĩa “xóa N hàng cũ nhất” — dùng subquery).

FK `ON DELETE CASCADE` biến một `DELETE` cha thành xóa cây — đo, không bất ngờ. `TRUNCATE` nhanh hơn `DELETE` toàn bảng nhưng khác trigger/quyền (mục 7).

**Ghi chú:** PostgreSQL `DELETE` tạo dead tuple; autovacuum phải theo kịp — parallel autovacuum / scoring 19: [internal.md](internal.md) §11. SQL Server: lock + log; optimized locking **2025** giảm escalation, không giảm WAL logic. Không `DELETE` trong txn mở qua UI.

## 5. MERGE vs upsert

### 5.1 MERGE (cả hai)

```sql
MERGE INTO dst AS d
USING src AS s
ON d.id = s.id
WHEN MATCHED THEN
    UPDATE SET val = s.val
WHEN NOT MATCHED THEN
    INSERT (id, val) VALUES (s.id, s.val)
WHEN NOT MATCHED BY SOURCE THEN     -- SQL Server lâu; PostgreSQL 17+
    DELETE;
```

PostgreSQL `MERGE` từ **15**; `WHEN NOT MATCHED BY SOURCE` từ **17** — **19 có**. `WHEN MATCHED AND predicate`. Một target khớp **nhiều** source → lỗi (SS **8672**; PG cardinality / “multiple assignments”).

SQL Server `MERGE` từng có bug concurrency (vá nhiều CU). Vẫn: khóa / isolation rõ; đừng `MERGE` + `NOLOCK`. Upsert cổ điển `UPDATE` rồi `IF @@ROWCOUNT = 0 INSERT` **race** — hai session cùng miss.

```sql
-- Race: cả hai session không thấy hàng, cả hai INSERT → unique fail hoặc duplicate
UPDATE dbo.Counters SET n = n + 1 WHERE Id = @id;
IF @@ROWCOUNT = 0
    INSERT INTO dbo.Counters (Id, n) VALUES (@id, 1);
```

`HOLDLOCK` / `SERIALIZABLE` trên target, hoặc `MERGE`, hoặc unique + retry. PostgreSQL: `INSERT … ON CONFLICT` cùng ý, một statement.

### 5.2 ON CONFLICT DO UPDATE / NOTHING

```sql
INSERT INTO counters (id, n)
VALUES (1, 1)
ON CONFLICT (id) DO UPDATE
SET n = counters.n + EXCLUDED.n
WHERE counters.n < 1000            -- optional: “not really update”
RETURNING *;
```

Cần unique index/constraint **đúng cột** (kể cả partial unique). `ON CONFLICT ON CONSTRAINT counters_pkey`. Không suy từ “cột nhìn giống khóa”.

`EXCLUDED` = hàng đề xuất insert. `DO NOTHING` bỏ qua conflict; `RETURNING` **không** ra hàng `DO NOTHING` (chỉ hàng insert thành công). Muốn trả hàng đã có mà không ghi: `DO SELECT` (5.3), không `DO NOTHING` + `RETURNING`.

Partial unique:

```sql
CREATE UNIQUE INDEX counters_active ON counters (id) WHERE active;

INSERT INTO counters (id, n, active)
VALUES (1, 1, true)
ON CONFLICT (id) WHERE active DO UPDATE
SET n = counters.n + 1;
```

Conflict target phải suy ra **đúng** index partial. Sai predicate `WHERE` = lỗi “no unique constraint”.

SQL Server **không** có `ON CONFLICT`. Dùng `MERGE` hoặc `UPDATE`+`INSERT` có khóa.

### 5.3 ON CONFLICT DO SELECT (PostgreSQL **19**, beta)

Insert hoặc **trả hàng đã có**, không sửa. Có thể khóa:

```sql
INSERT INTO t (id, val) VALUES (1, 'x')
ON CONFLICT (id) DO SELECT
FOR UPDATE
RETURNING *;
```

| Nhánh | Conflict? | Ghi? | `RETURNING` | Khóa tùy chọn |
|---|---|---|---|---|
| (không mệnh đề) | lỗi unique | insert nếu không | hàng mới | — |
| `DO NOTHING` | bỏ qua | không | không hàng conflict | không |
| `DO UPDATE` | có | **ghi đè** (trừ `WHERE` false) | hàng sau update | row lock update |
| `DO SELECT` **19** | có | **không** | hàng **đã có** | `FOR UPDATE` / `SHARE` |

Điền “get-or-create” / idempotency: lần 1 insert `'x'`; lần 2 cùng `id` trả hàng cũ, **giữ** `val` cũ (không overwrite thành `'x'` nếu khác). `DO UPDATE SET val = EXCLUDED.val` thì ghi đè.

`FOR UPDATE` trên `DO SELECT`: khóa hàng tồn tại cho read-modify-write tiếp trong txn. Không khóa nếu không ghi `FOR UPDATE` — session khác vẫn update được ngay sau `RETURNING`.

Không có trên SQL Server — gần:

```sql
-- SS: MERGE no-op matched + OUTPUT; hoặc HOLDLOCK + insert
MERGE dbo.T AS d
USING (SELECT 1 AS Id, 'x' AS Val) AS s
ON d.Id = s.Id
WHEN MATCHED THEN UPDATE SET Val = d.Val      -- no-op, vẫn lock kiểu update
WHEN NOT MATCHED THEN INSERT (Id, Val) VALUES (s.Id, s.Val)
OUTPUT inserted.*;
```

No-op `UPDATE` vẫn là update (trigger, CES, version) — **không** tương đương `DO SELECT` (không ghi). `HOLDLOCK` + `SELECT` rồi `INSERT` = hai statement, race trừ isolation/khóa đúng.

**Ghi chú:** **Beta** 19. Unique violation vẫn cần index unique. Race: `DO SELECT FOR UPDATE` vs `DO UPDATE` khác nghiệp vụ. Không bịa `DO SELECT WHERE`. Partial unique: cùng luật conflict target như `DO UPDATE`.

### 5.4 MERGE vs upsert — khi nào

| Nhu cầu | PostgreSQL | SQL Server |
|---|---|---|
| Insert hoặc cộng counter | `ON CONFLICT DO UPDATE` | `MERGE` / `UPDATE`+retry |
| Insert hoặc trả hàng cũ, không đè | `DO SELECT` **19** | `MERGE` no-op (vẫn update) hoặc khóa tay |
| Bỏ qua trùng | `DO NOTHING` | `MERGE` không nhánh matched / `IGNORE` không có |
| Matched update *khác* + xóa source-only | `MERGE` + `NOT MATCHED BY SOURCE` | `MERGE` |
| Nhiều nguồn → một target | `MERGE` **lỗi**; `ON CONFLICT` một insert row | `MERGE` **8672** |
| Fan-out `UPDATE FROM` | im lặng sai | im lặng last-write; `MERGE` lỗi |

`ON CONFLICT` = *insert-first*, va unique index. `MERGE` = *join* source⊖target, rồi nhánh. Source thiếu unique trên khóa `ON` → `MERGE` fail; `INSERT … ON CONFLICT` từng hàng source (nhiều hàng source cùng khóa = nhiều lần conflict, kết quả theo thứ tự **không** như `MERGE` atomic một target).

```sql
-- PG: hai hàng VALUES cùng id — không phải MERGE cardinality
INSERT INTO t (id, val)
VALUES (1, 'a'), (1, 'b')
ON CONFLICT (id) DO UPDATE SET val = EXCLUDED.val;
-- Thường: một insert, một update (hoặc hai update) — thứ tự/ visib. phức tạp; đừng dựa
```

Chuẩn hóa source **một hàng / khóa** trước mọi upsert.

Retry unique (`23505` PG / 2627 SS): idempotent `INSERT` trong loop ngắn, backoff. Đừng nuốt mọi lỗi. `DO SELECT` 19 giảm nhu cầu “insert rồi catch duplicate rồi SELECT” — một statement, vẫn cần unique.

**Ghi chú:** `ON CONFLICT` không thay `MERGE` đa nhánh. Không port `DO SELECT` sang T-SQL bằng một từ khóa. Isolation: cả hai vẫn race với `DELETE` xen giữa nếu không khóa — [transactions.md](transactions.md).

SQL Server upsert an toàn hơn `IF @@ROWCOUNT` khi khóa range đúng:

```sql
-- SS: khóa key, tránh hai INSERT
BEGIN TRAN;
SELECT Id FROM dbo.Counters WITH (UPDLOCK, HOLDLOCK, ROWLOCK) WHERE Id = @id;
IF @@ROWCOUNT = 0
    INSERT INTO dbo.Counters (Id, n) VALUES (@id, 1);
ELSE
    UPDATE dbo.Counters SET n = n + 1 WHERE Id = @id;
COMMIT TRAN;
```

`HOLDLOCK` = range/key serializable trên predicate — phantom insert bị chặn. Đắt hơn `ON CONFLICT` một statement. Unique index vẫn bắt buộc (hai session trước khi có hàng: range lock). `MERGE` một statement thường gọn hơn pattern này; vẫn unique-hóa source.

`WHEN MATCHED AND d.version = s.version THEN UPDATE …` (optimistic) + `WHEN MATCHED AND d.version <> s.version THEN` không làm gì / lỗi: cả hai engine hỗ trợ predicate trên nhánh. Không nhánh → hàng bỏ qua, không báo — kiểm `@@ROWCOUNT` / `RETURNING`.

## 6. OUTPUT / RETURNING

```sql
-- SQL Server
INSERT INTO dbo.Orders (CustomerId)
OUTPUT inserted.Id, inserted.CustomerId
VALUES (1);

UPDATE dbo.Orders
SET Total = 0
OUTPUT deleted.Total AS old_total, inserted.Total AS new_total
WHERE Id = 1;

DELETE FROM dbo.Orders
OUTPUT deleted.Id INTO @gone
WHERE Id = 1;
```

`inserted` / `deleted` là bảng ảo. `OUTPUT INTO` table / table variable. Hạn chế: `OUTPUT` vào bảng đang mutate — thường lỗi; dùng table variable / temp.

Trigger `INSTEAD OF` + `OUTPUT`: thấy dữ liệu **sau** trigger — đọc docs, đừng giả định “hàng đề xuất”.

```sql
-- PostgreSQL
INSERT INTO orders (customer_id) VALUES (1) RETURNING *;

UPDATE orders SET total = 0 WHERE id = 1
RETURNING id, total;

DELETE FROM orders WHERE id = 1
RETURNING *;
```

**PostgreSQL 18+:** `RETURNING` cũ và mới trên `UPDATE`/`DELETE`:

```sql
UPDATE orders
SET total = 0
WHERE id = 1
RETURNING WITH (OLD AS o, NEW AS n)
    o.total AS old_total, n.total AS new_total;

DELETE FROM orders
WHERE id = 1
RETURNING WITH (OLD AS o)
    o.id, o.total;
```

`INSERT` chỉ có hàng mới (`NEW` / `RETURNING *`). `DELETE` không có `NEW`. `DO SELECT` `RETURNING` = hàng **đã có** (không phải `EXCLUDED`).

**Ghi chú:** `RETURNING` chạy sau BEFORE trigger, thấy hàng sẽ lưu; AFTER trigger vẫn chạy trong statement. Client lấy `RETURNING` thay `SELECT` ngay sau để tránh race. SQL Server `SCOPE_IDENTITY()` vs `OUTPUT`: nhiều hàng / parallel → `OUTPUT` an toàn hơn.

## 7. TRUNCATE vs CES PREVIEW

```sql
TRUNCATE TABLE logs;
TRUNCATE TABLE logs RESTART IDENTITY;     -- PostgreSQL
TRUNCATE TABLE a, b;                      -- PostgreSQL nhiều bảng (FK vòng)
```

| | SQL Server | PostgreSQL |
|---|---|---|
| Trong txn user | Hạn chế / lock mạnh; đừng giả định rollback như DML | Rollback được (MVCC catalog) |
| Trigger `DELETE` | Không fire | Không fire `DELETE`; có trigger `TRUNCATE` |
| Identity / sequence | Reset identity | `RESTART IDENTITY` / `CONTINUE IDENTITY` |
| FK tới bảng | Thường **cấm** TRUNCATE | `CASCADE` hoặc truncate cả nhóm |
| Log | Minimal | WAL catalog + hint bits; nhanh hơn `DELETE` |
| Logical / CDC / CES | Event riêng hoặc **không** từng hàng | `TRUNCATE` message, không stream từng hàng |

SQL Server: quyền `ALTER` (cao hơn `DELETE`); heap/clustered empty. PostgreSQL: `REPACK`/`VACUUM` **không** thay truncate khi muốn rỗng bảng — [ddl.md](ddl.md) §10.

### 7.1 CES PREVIEW (SQL Server 2025)

**Change Event Streaming:** DML → Event Hubs / Fabric Eventstream (CloudEvents JSON/Avro). **PREVIEW** + `PREVIEW_FEATURES`. Entra từ CU3 (Arc/Azure VM) — đối chiếu Learn/CU.

CES **giữ log** như CDC — consumer chậm = đầy disk. [concurrency.md](concurrency.md) §11, [internal.md](internal.md) §15.

| | CES **PREVIEW** | CDC | `TRUNCATE` | Fabric mirroring (GA) |
|---|---|---|---|---|
| Mục đích | Event stream | Capture instance / log reader | Rỗng bảng nhanh | Replica OneLake |
| Từng hàng `INSERT`/`UPDATE`/`DELETE` | Kỳ vọng stream | Có | Không (không từng hàng) | Khác pipeline |
| `TRUNCATE` | **Không giả định** — xác nhận docs/CU hiện tại trước khi dựa | Thường **không** từng hàng; một số cấu hình fail/`TRUNCATE` cấm | Chính nó | Không phải CES |
| Production | Chỉ khi chấp nhận breaking CU | GA (không phải CES) | GA | GA; ≠ CES |

Không bật CES + mirroring + CDC cùng bảng mà không đo log reuse. Synapse Link **discontinued** — không nhầm mirroring.

`DELETE` hàng loạt → nhiều event CES; `TRUNCATE` → tối đa event kiểu DDL/truncate (nếu có) — pipeline “đếm hàng xóa” **vỡ** nếu ai đó truncate.

PostgreSQL logical decoding / subscription: `TRUNCATE` là message riêng (`publish_via_partition_root`, replica identity không áp từng hàng). `wal_level` / publication — [internal.md](internal.md), [ddl.md](ddl.md) sequence pub.

**Ghi chú:** CES không phải API load (`BULK INSERT`). Không invent “CES bắt TRUNCATE”. Replica: xác nhận truncate trước khi ETL “empty + reload” trên bảng đang stream.

## 8. FOR PORTION OF (PostgreSQL 19)

Application-time period: PG **18** `WITHOUT OVERLAPS` trên rangetype / constraint. PG **19** thêm DML `FOR PORTION OF`: cắt khoảng, **không** update/xóa cả hàng nếu hàng dài hơn portion. **Beta**.

```sql
UPDATE products
FOR PORTION OF valid_at FROM DATE '2026-01-01' TO DATE '2026-07-01'
SET price = 99
WHERE sku = 'ABC';

DELETE FROM products
FOR PORTION OF valid_at FROM DATE '2028-01-01' TO DATE '2029-01-01'
WHERE sku = 'ABC';

-- Multirange: bắt buộc dạng ngoặc
DELETE FROM products
FOR PORTION OF valid_at ('[2028-01-01,)'::datemultirange)
WHERE sku = 'ABC';
```

Bound **hằng** (`now()` được; **không** column ref). Hàm hỗ trợ: `range_minus_multi` / `multirange_minus_multi` (engine dùng khi cắt). Constraint temporal: [constraints.md](constraints.md).

SQL Server temporal `SYSTEM_VERSIONING` / `FOR SYSTEM_TIME` là **system-time** (history tự động), **không** có `FOR PORTION OF`. Sửa lịch sử application-time trên SS: tự quản period + không `WITHOUT OVERLAPS` native — constraint/`TRIGGER`.

### 8.1 Leftover

Hàng một range `[2025-01-01, 2027-01-01)` + `UPDATE FOR PORTION OF` `[2026-01-01, 2026-07-01)`:

1. Phần giao portion được **update** (`price = 99`), bound thu hẹp còn `[2026-01-01, 2026-07-01)`.
2. Engine **insert leftover** (mảnh không đụng, giá **cũ**):
   - leftover trái `[2025-01-01, 2026-01-01)`
   - leftover phải `[2026-07-01, 2027-01-01)`

Range: **0–2** leftover. Multirange: **0–1** leftover (cắt lỗ trong multi). Leftover = `INSERT` thật: trigger `INSERT` / `IDENTITY` / CES-logical **có thể** fire — kiểm tra, đừng giả định “chỉ UPDATE”.

`WITHOUT OVERLAPS`: leftover **không được chồng** hàng khác cùng khóa. Fail constraint nếu đã có hàng chiếm `[2025, 2026)`. Đo trước khi cắt.

`COPY` / `TRUNCATE` **không** hiểu portion — load/rỗng cả hàng.

Không bịa `FOR PORTION OF SYSTEM_TIME`. Không bitemporal đầy đủ trừ khi tự quản system-time.

### 8.2 Race READ COMMITTED

Session khác đổi bound giữa lúc đọc và cắt leftover → leftover **mất** hoặc chồng — documented hazard ở RC.

Timeline:

1. Session A đọc hàng `[2025, 2027)`, price 80; bắt đầu cắt portion `[2026, 2026-07)`.
2. Session B (RC) commmit đổi bound / xóa / cắt khác trên cùng `sku`.
3. A insert leftover theo bound **cũ** → lỗ khoảng, chồng, hoặc mất mảnh B vừa ghi.

Nên:

```sql
BEGIN;
SELECT * FROM products
WHERE sku = 'ABC'
FOR UPDATE;

UPDATE products
FOR PORTION OF valid_at FROM DATE '2026-01-01' TO DATE '2026-07-01'
SET price = 99
WHERE sku = 'ABC';
COMMIT;
```

`FOR UPDATE` **cùng predicate** (và khóa mọi hàng `sku` liên quan period) trước portion. Isolation `REPEATABLE READ` / `SERIALIZABLE`: khóa đó không bắt buộc theo docs 19 nhưng **test**; retry `40001` — [transactions.md](transactions.md).

Hai txn cắt portion **chồng lấn** trên cùng hàng: không `FOR UPDATE` = leftover race. Đừng song song worker theo `sku` mà không khóa.

Trigger / identity / stream khi cắt:

| Sự kiện | `UPDATE` thường | `UPDATE FOR PORTION OF` (19) |
|---|---|---|
| Trigger `UPDATE` | 1 | 1 trên mảnh giao (engine cắt) |
| Trigger `INSERT` | 0 | **0–2** leftover range |
| `RETURNING` | 1 hàng | hàng sau cắt — leftover có thể không nằm `RETURNING` cùng lúc như “mọi mảnh”; đo bản beta |
| Identity/sequence | không | leftover **INSERT** có thể lấy identity mới nếu bảng có |
| CES / logical | 1 update | update + insert leftover (logical); CES SS **không** có portion |

`DELETE FOR PORTION OF` tương tự: xóa khoảng giao, leftover giữ phần ngoài — cũng INSERT mảnh còn lại, không phải “cập nhật bound im lặng” nếu engine tách hàng.

**Ghi chú:** **Beta** 19. Leftover tăng số hàng — `COUNT(*)` “một SKU một hàng” vỡ. Application-time ≠ system-versioned SS. `DELETE FOR PORTION OF` cũng leftover (giữ mảnh ngoài khoảng xóa). Không song song hai worker cùng `sku` ở RC.

## 9. COPY / BULK

| | SQL Server | PostgreSQL |
|---|---|---|
| Client | `bcp`, `BULK INSERT`, `SqlBulkCopy` | `COPY`, `\copy` (client) |
| File server | `BULK INSERT t FROM 'path'` | `COPY t FROM 'path'` (quyền siêu user / role) |
| Tốc độ | Minimal log khi đủ điều kiện (`TABLOCK`, recovery, …) | `COPY` + drop index / `UNLOGGED` staging |
| 19 / 2025 | CES **PREVIEW** không thay bulk load | `COPY FROM` text/CSV **SIMD**; tùy chọn dưới |

```sql
-- PostgreSQL
COPY orders (id, total)
FROM STDIN
WITH (FORMAT csv, HEADER true);

COPY orders FROM '/tmp/orders.csv' WITH (FORMAT csv, HEADER true, FREEZE);  -- điều kiện: bảng vừa CREATE/TRUNCATE cùng txn
```

`\copy` chạy trong client, file local — không cần quyền file trên server. PG 12+: `COPY … WHERE` (lọc lúc load).

### 9.1 PostgreSQL 19 — COPY

| Tùy chọn / hành vi | Việc | Cảnh báo |
|---|---|---|
| SIMD text/CSV `COPY FROM` | Nhanh hơn parse | Không đổi ngữ nghĩa CSV |
| Skip **nhiều** dòng header | File có preamble | Đếm đúng số dòng skip |
| `ON_ERROR SET_NULL` | Input **invalid** → `NULL` (không abort) | Nuốt dữ liệu bẩn — **cấm** load tài chính |
| `COPY TO` JSON | Export JSON | ≠ `json_agg` (không `GROUP BY`) |
| `FORCE_ARRAY` | `COPY TO` JSON array wrap | Đối chiếu docs 19; đừng bịa tên option khác |
| `COPY TO` partitioned table | Dump trực tiếp bảng cha | Logical sync cũng lợi |
| `COPY FROM … WHERE` **cấm system column** | `xmin`, `ctid`, `xmax`, … | Giá trị system column không xác định lúc COPY — **incompatibility 19** |

```sql
-- 19: SET_NULL khi ô không parse — mất tín hiệu lỗi
COPY staging (id, amount)
FROM '/tmp/p.csv'
WITH (FORMAT csv, HEADER true, ON_ERROR SET_NULL);

-- Cấm (19): WHERE trên ctid/xmin
COPY orders FROM '/tmp/o.csv' WITH (FORMAT csv)
WHERE ctid IS NOT NULL;          -- lỗi: system column
```

Không invent `COPY BINARY` option không đọc docs. `ON_ERROR` khác `IGNORE` từng engine — chỉ dùng tên đã document (`SET_NULL`). Encoding/NUL: vẫn abort nếu không SET_NULL.

### 9.2 SQL Server BULK

```sql
BULK INSERT dbo.Orders
FROM 'C:\data\orders.csv'
WITH (
    FORMAT = 'CSV',
    FIRSTROW = 2,
    TABLOCK,
    KEEPIDENTITY
);
```

Minimal logging: recovery bulk-logged/simple, `TABLOCK`, điều kiện heap/empty clustered — đọc Learn, đừng giả định mọi `BULK INSERT` đều minimal. `FIRE_TRIGGERS` đổi hành vi và chi phí.

Staging: PG `UNLOGGED` (mất khi crash); SQL Server heap + `TABLOCK`. Load xong `INSERT … SELECT` + `ON CONFLICT`/`MERGE`. Index: drop/disable → load → rebuild thường nhanh hơn maintain từng hàng — [indexes.md](indexes.md), [ddl.md](ddl.md).

`SqlBulkCopy` mặc định không fire trigger / check constraint tùy `SqlBulkCopyOptions`. CES (2025 **PREVIEW**) stream DML ra Event Hubs — không phải API load.

Bulk vs stream — chọn sai công cụ:

| Việc | Nên | Không |
|---|---|---|
| Load 10 triệu hàng | `COPY` / `BULK INSERT` + staging | Từng `INSERT` + CES làm “audit load” |
| CDC từng thay đổi OLTP | Logical / CDC / CES **PREVIEW** | `TRUNCATE` + reload rồi tin stream đủ hàng |
| Rỗng bảng nightly | `TRUNCATE` (nếu không cần trigger DELETE / event từng hàng) | `DELETE` không `WHERE` giờ cao điểm |
| File CSV bẩn | Abort `COPY`; sửa file | `ON_ERROR SET_NULL` rồi `SUM(amount)` |

**Ghi chú:** Script `COPY FROM … WHERE ctid = …` trên 18 có thể chạy; **19 từ chối**. `FORCE_ARRAY` chỉ nhánh JSON `COPY TO`. Parallel autovacuum sau bulk PG — [internal.md](internal.md). `FREEZE` + `COPY` cùng txn sau `CREATE`/`TRUNCATE` — điều kiện hẹp, đừng thêm vào job tùy tiện.

## 10. Worked examples

### 10.1 Đơn giản — insert + lấy id

```sql
-- SQL Server
INSERT INTO dbo.Orders (CustomerId, Total)
OUTPUT inserted.Id
VALUES (1, 99.50);

-- PostgreSQL
INSERT INTO orders (customer_id, total)
VALUES (1, 99.50)
RETURNING id;
```

### 10.2 Trung bình — upsert counter vs get-or-create

```sql
-- PostgreSQL: cộng counter
INSERT INTO counters (id, n)
VALUES (@id, 1)
ON CONFLICT (id) DO UPDATE
SET n = counters.n + 1
RETURNING n;

-- PostgreSQL 19: lấy hàng cũ, không đè val
INSERT INTO tokens (id, val)
VALUES (@id, @val)
ON CONFLICT (id) DO SELECT
FOR UPDATE
RETURNING *;

-- SQL Server counter
MERGE dbo.Counters AS d
USING (SELECT @id AS Id) AS s
ON d.Id = s.Id
WHEN MATCHED THEN UPDATE SET n = d.n + 1
WHEN NOT MATCHED THEN INSERT (Id, n) VALUES (s.Id, 1)
OUTPUT inserted.n;
```

Bọc isolation / khóa nếu `n` là invariant (không âm, trần). Atomic `UPDATE … SET n = n + 1 WHERE n < trần` đôi khi đủ, không cần `MERGE`. `DO SELECT` **không** tăng `n`.

### 10.3 Nâng cao — lô xóa + portion + leftover an toàn

```sql
-- PG 19: khóa, cắt giá theo lịch, xóa log cũ theo lô
BEGIN;

SELECT 1 FROM products WHERE sku = 'ABC' FOR UPDATE;

UPDATE products
FOR PORTION OF valid_at FROM DATE '2026-01-01' TO DATE '2026-07-01'
SET price = 99
WHERE sku = 'ABC';
-- leftover: INSERT mảnh 2025–2026 và 2026-07–… giá cũ; trigger INSERT có thể chạy

WITH batch AS (
    SELECT ctid FROM user_logs
    WHERE created_at < DATE '2025-01-01'
    ORDER BY created_at
    FOR UPDATE SKIP LOCKED
    LIMIT 5000
)
DELETE FROM user_logs u
USING batch b
WHERE u.ctid = b.ctid
RETURNING u.id;

COMMIT;
```

SQL Server tương đương portion: **không có** — cập nhật bảng period tự quản + history. Xóa lô: `DELETE TOP (5000) …` trong vòng lặp, `UPDLOCK`/`READPAST` trên queue. Truncate log: **không** nếu bảng đang CES **PREVIEW** mà pipeline đếm từng `DELETE`.

Leftover trước/sau (một hàng range):

```text
Trước:  sku=ABC  valid_at=[2025-01-01, 2027-01-01)  price=80
UPDATE FOR PORTION OF [2026-01-01, 2026-07-01) SET price=99

Sau (3 hàng, cùng sku, WITHOUT OVERLAPS):
  [2025-01-01, 2026-01-01)  80     -- leftover INSERT
  [2026-01-01, 2026-07-01)  99     -- portion đã UPDATE
  [2026-07-01, 2027-01-01)  80     -- leftover INSERT
```

Hai session RC **không** `FOR UPDATE`: B cắt `[2026-06-01, 2026-12-01)` trong lúc A cắt `[2026-01-01, 2026-07-01)` → leftover A/B chồng hoặc lỗ — constraint fail hoặc mất giá. Khóa `sku` trước (mục 8.2).

### 10.4 COPY 19 — header, SET_NULL, không system col

```sql
BEGIN;
CREATE TEMP TABLE load_orders (id int, total numeric, note text) ON COMMIT DROP;
COPY load_orders (id, total, note)
FROM '/tmp/orders.csv'
WITH (
    FORMAT csv,
    HEADER true,          -- 19: skip nhiều dòng header nếu file đòi (docs: số dòng)
    ON_ERROR SET_NULL     -- ô amount bẩn → NULL; CHECK sau
);
-- Không: WHERE xmin = … / ctid
INSERT INTO orders (id, total, note)
SELECT id, total, note FROM load_orders
WHERE total IS NOT NULL     -- loại hàng SET_NULL
ON CONFLICT (id) DO UPDATE
SET total = EXCLUDED.total;
COMMIT;
```

Tài chính: **bỏ** `ON_ERROR SET_NULL`, để `COPY` abort, sửa file.

### 10.5 MERGE xóa source-only vs upsert

```sql
-- Cả hai (PG 17+ / SS): đồng bộ dst theo src, xóa hàng không còn trên src
MERGE INTO dst AS d
USING src AS s
ON d.id = s.id
WHEN MATCHED AND d.val IS DISTINCT FROM s.val THEN
    UPDATE SET val = s.val
WHEN NOT MATCHED THEN
    INSERT (id, val) VALUES (s.id, s.val)
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
```

`ON CONFLICT` **không** làm nhánh xóa. Unique-hóa `src` trên `id` trước — thiếu → 8672 / cardinality.

## 11. Best practices & checklist

- Liệt kê cột `INSERT`; txn ngắn; `XACT_ABORT ON` (SS).
- Đếm `DISTINCT` PK target trước `UPDATE`/`DELETE` có `FROM`/`USING`.
- Upsert: PG `ON CONFLICT`; get-or-create không đè: `DO SELECT` **19**; đa nhánh / xóa source-only: `MERGE`.
- Nguồn `MERGE`/`INSERT` unique trên khóa.
- Lấy id mới: `RETURNING` / `OUTPUT`, không `MAX(id)+1`.
- Xóa lớn: lô + vacuum/index maintain.
- Temporal PG 19: `FOR UPDATE` trước portion ở RC; hiểu leftover = INSERT.
- Bulk: staging + constraint sau; `ON_ERROR SET_NULL` không cho tiền.
- `TRUNCATE` vs `DELETE`: trigger, identity, CES/logical.
- Sequence/identity lỗ là bình thường.

```text
□ WHERE trên mọi UPDATE/DELETE production
□ Nguồn UPDATE 1 hàng / target
□ Unique đúng cho ON CONFLICT / MERGE
□ DO SELECT ≠ DO UPDATE ≠ DO NOTHING
□ OUTPUT/RETURNING cột cần, không SELECT lại
□ TRUNCATE vs DELETE đã chọn có chủ đích
□ CES PREVIEW: không giả định TRUNCATE
□ FOR PORTION: khóa hoặc RR/SSI; leftover constraint
□ COPY: không system col WHERE; SET_NULL có chủ đích
□ COPY/BULK quyền file + encoding
```

## 12. Bẫy khi review

- `UPDATE`/`DELETE` không `WHERE`.
- PG `UPDATE … FROM` staging trùng khóa — im lặng sai.
- `MERGE` fan-out source (SS lỗi; vẫn phải unique-hóa).
- `ON CONFLICT` thiếu unique / sai cột partial.
- `DO NOTHING` + kỳ vọng `RETURNING` hàng cũ.
- `DO SELECT` tưởng `DO UPDATE` (không đè vs đè).
- `NOT IN` trong `DELETE … WHERE id NOT IN (SELECT nullable)`.
- `IDENTITY_INSERT` quên `OFF`.
- `OVERRIDING` nhầm ALWAYS vs BY DEFAULT.
- `OUTPUT` vào cùng bảng đang ghi.
- Tin `SCOPE_IDENTITY()` sau insert nhiều hàng / trigger.
- `TRUNCATE` trên bảng bị FK (SS) / quên `CASCADE` (PG).
- `TRUNCATE` trên bảng CES/logical rồi tin stream đủ từng hàng.
- CES **PREVIEW** như CDC đầy đủ / production.
- `FOR PORTION OF` ở RC không khóa — leftover race.
- Port system-versioned SS sang `FOR PORTION OF` (khác mô hình).
- `COPY FROM … WHERE ctid = …` trên PG 19 (system column cấm).
- `ON_ERROR SET_NULL` load số tiền.
- Trigger BEFORE đổi hàng vs `RETURNING`; leftover fire INSERT trigger.

## 13. Version gates

| Mục | SQL Server | PostgreSQL |
|---|---|---|
| `MERGE` | lâu (vá concurrency) | **15+** |
| `WHEN NOT MATCHED BY SOURCE` | lâu | **17+** (có trên 19) |
| `ON CONFLICT DO UPDATE` | không | **9.5+** |
| `ON CONFLICT DO SELECT` | không | **19 beta** |
| `OUTPUT` | lâu | dùng `RETURNING` |
| `RETURNING WITH (OLD, NEW)` | không | **18+** |
| `OVERRIDING SYSTEM/USER VALUE` | không (`IDENTITY_INSERT`) | identity chuẩn |
| `FOR PORTION OF` | không | **19 beta** |
| Application-time `WITHOUT OVERLAPS` | không | **18+** |
| System-versioned temporal | có | extension / tự quản |
| `COPY` SIMD text/CSV | — | **19** |
| `COPY` `ON_ERROR SET_NULL` / `FORCE_ARRAY` / JSON TO | — | **19** |
| `COPY FROM WHERE` system col cấm | — | **19** |
| `BULK INSERT` / `bcp` | lâu | — |
| Optimized locking | **2025** | MVCC |
| Change Event Streaming | **2025 PREVIEW** | logical decoding / `wal_level` |
| Fabric mirroring | **2025 GA** (≠ CES) | — |
