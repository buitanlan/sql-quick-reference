# Ràng buộc (Constraints)

> **Baseline:** SQL Server **2025** (17.x) · PostgreSQL **19**.  
> Constraint là invariant **engine** — không phải validation app. Isolation không thay CHECK/FK. `NOCHECK` / `NOT VALID` / deferred / `NOT ENFORCED` đổi *khi nào* kiểm, không xóa rule.

Constraint quyết định hàng nào được commit. PK/UNIQUE (kể cả `NULLS NOT DISTINCT`), FK + hành động xóa/sửa, CHECK (NULL **qua**), `EXCLUDE` / temporal `WITHOUT OVERLAPS` (PostgreSQL), deferred (chỉ PG), `NOCHECK` untrusted (SQL Server) vs `NOT VALID` (PG) — lệch dialect dễ port sai. App-only unique = race. DDL lock: [ddl.md](ddl.md). Isolation lúc commit deferred: [transactions.md](transactions.md). Index đứng sau unique/FK: [indexes.md](indexes.md). Leftover `FOR PORTION OF`: [dml.md](dml.md).

PostgreSQL 19 **beta**: FK check nhanh hơn (implementation, không đổi ngữ nghĩa); `ALTER … CONSTRAINT … [NOT] ENFORCED` cho **CHECK** (trước 19: ENFORCED chủ yếu FK). SQL Server: không `EXCLUDE`, không defer FK.

## 1. Tổng quan & triết lý

Constraint chạy trong statement hoặc lúc `COMMIT` (deferred PG). Trigger bổ sung, không thay unique/FK: trigger có thể bypass, khó song song, dễ quên trên bulk/`COPY`.

Ba câu hỏi trước mỗi constraint:

1. **Invariant gì?** Một hàng (CHECK, NOT NULL) vs nhiều hàng (UNIQUE, EXCLUDE) vs hai bảng (FK) vs period (WITHOUT OVERLAPS).
2. **NULL?** UNIQUE mặc định nhiều NULL; CHECK `UNKNOWN` qua; FK NULL thường không đòi cha.
3. **Khi nào kiểm?** Immediate vs deferred vs `NOT VALID` (hàng cũ) vs `NOCHECK` (SS, untrusted / tắt) vs `NOT ENFORCED` (PG, không kiểm kể cả hàng mới).

Đổi PK trên bảng lớn = rewrite + mọi FK. Disable FK “cho nhanh ETL” rồi quên `WITH CHECK` = optimizer mất join elimination *và* dữ liệu mồ côi.

```text
Hàng mới    Hàng cũ         Tên
────────────────────────────────────────────────
Kiểm        Quét lúc ADD    ADD … (mặc định)
Kiểm        Không quét      NOT VALID (PG) / WITH NOCHECK ADD (SS untrusted)
Không kiểm  Không           NOCHECK (SS disabled) / NOT ENFORCED (PG)
Kiểm lúc COMMIT             DEFERRABLE (PG)
```

Ba cột giữa **không** thay nhau — mục 11–12.

## 2. PRIMARY KEY

Một PK mỗi bảng. PK ⇒ `NOT NULL` trên mọi cột khóa + unique index (clustered mặc định SQL Server trừ khi đã có CX / chỉ định `NONCLUSTERED`).

```sql
CREATE TABLE users (
    id         int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,  -- PG
    tenant_id  int NOT NULL,
    ext_id     text NOT NULL,
    email      text NOT NULL,
    UNIQUE (tenant_id, ext_id)
);

-- SQL Server
CREATE TABLE dbo.Users (
    Id        int IDENTITY(1,1) NOT NULL
        CONSTRAINT PK_Users PRIMARY KEY CLUSTERED,
    TenantId  int NOT NULL,
    ExtId     nvarchar(64) NOT NULL,
    Email     nvarchar(320) NOT NULL,
    CONSTRAINT UQ_Users_tenant_ext UNIQUE (TenantId, ExtId)
);
```

Composite PK: `(tenant_id, id)` khi identity toàn cục không đủ. Clustered SS nên hẹp, tăng dần — [indexes.md](indexes.md) §3.

PostgreSQL 18+: PK temporal `PRIMARY KEY (id, valid_at WITHOUT OVERLAPS)` — mục 9. Không phải SQL Server `PERIOD FOR SYSTEM_TIME`.

**Ghi chú:** Unique index ≠ PK: PK được FK tham chiếu; chỉ một PK. Nhiều UNIQUE được. Surrogate `id` không miễn UNIQUE nghiệp vụ (`tenant_id, ext_id`). JSON INDEX SS đòi **clustered PK** — [json.md](json.md), [indexes.md](indexes.md).

## 3. UNIQUE & NULLS NOT DISTINCT

SQL NULL ≠ NULL: unique mặc định **cho phép nhiều hàng NULL** trên cả hai engine.

| | SQL Server | PostgreSQL |
|---|---|---|
| Mặc định | Nhiều NULL | Nhiều NULL (`NULLS DISTINCT`) |
| Cấm trùng NULL | Filtered unique `WHERE col IS NOT NULL` **không** cấm nhiều NULL — chỉ unique phần non-null | `UNIQUE NULLS NOT DISTINCT` (**15+**) |
| Composite | NULL một cột: hàng khác NULL cùng vị trí vẫn được (NULL không bằng) | Giống, trừ `NULLS NOT DISTINCT` |

```sql
-- PostgreSQL 15+
CREATE TABLE t (
    email text UNIQUE NULLS NOT DISTINCT
);
ALTER TABLE t ADD CONSTRAINT uq_email UNIQUE NULLS NOT DISTINCT (email);

-- SQL Server: unique phần non-null (nhiều NULL vẫn được)
CREATE UNIQUE INDEX ux_users_email
    ON dbo.Users (Email)
    WHERE Email IS NOT NULL;
```

Muốn “tối đa một NULL” trên SS: không có `NULLS NOT DISTINCT`. Cách gần: cột sentinel, computed `ISNULL`, hoặc filtered không đủ — thiết kế `NOT NULL`.

Composite `NULLS NOT DISTINCT`: hai hàng `(NULL, 1)` trùng. Mặc định DISTINCT: hai hàng đó được (NULL ≠ NULL). Port unique “cặp (tenant, phone) phone optional không trùng” — review từng cột NULL.

**Ghi chú:** Port unique “email optional nhưng không trùng” từ PG `NULLS NOT DISTINCT` sang SS filtered index = **sai** (hai NULL lọt). Review dialect gates.

## 4. FOREIGN KEY: hành động

```sql
ALTER TABLE orders
    ADD CONSTRAINT orders_customer_fk
    FOREIGN KEY (customer_id) REFERENCES customers (id)
    ON DELETE RESTRICT
    ON UPDATE CASCADE;

-- SQL Server
ALTER TABLE dbo.Orders WITH CHECK
    ADD CONSTRAINT FK_Orders_Customers
    FOREIGN KEY (CustomerId) REFERENCES dbo.Customers (Id)
    ON DELETE NO ACTION
    ON UPDATE NO ACTION;
```

| Hành động | Khi xóa/sửa cha |
|---|---|
| `NO ACTION` | Từ chối nếu còn con. PG: có thể **defer** (kiểm lúc COMMIT). SS: immediate reject |
| `RESTRICT` | PG: immediate, không defer. SS: `ON DELETE RESTRICT` (2019+ tương đương chặn; historically `NO ACTION`) |
| `CASCADE` | Xóa/sửa con theo. Cây sâu / cycle = thảm họa |
| `SET NULL` | Cột con nullable |
| `SET DEFAULT` | Cột có default hợp lệ (trỏ cha còn sống) |

Self-FK, hai bảng vòng: PG deferred (mục 10); SS insert theo thứ tự hoặc disable tạm.

Match composite: mọi cột FK NULL hoặc mọi cột khớp cha (MATCH SIMPLE mặc định — một NULL = không đòi cha). `MATCH FULL` (PG): một NULL + một non-null = lỗi.

**Ghi chú:** `ON UPDATE CASCADE` trên PK surrogate hiếm khi cần (PK không đổi). `CASCADE` xóa đơn hàng khi xóa khách — thường sai nghiệp vụ; dùng `RESTRICT` + soft-delete.

PostgreSQL **19:** kiểm tra FK **nhanh hơn** (implementation) — không đổi ngữ nghĩa, không bỏ index cột con.

## 5. FK phải được index

**Không** engine nào tự tạo index trên cột *con* khi `ADD FOREIGN KEY`. Unique/PK phía *cha* đã có index. `DELETE`/`UPDATE` cha phải tìm con → thiếu index = seq scan + lock rộng.

```sql
-- Bắt buộc sau mỗi FK (tên ví dụ)
CREATE INDEX ix_orders_customer ON orders (customer_id);

-- SQL Server
CREATE INDEX IX_Orders_CustomerId ON dbo.Orders (CustomerId);
```

Index này còn phục vụ `JOIN` / `WHERE customer_id = ?`. Composite FK: index khớp thứ tự cột FK hoặc prefix.

**Ghi chú:** Reviewer thấy FK mới mà không thấy `CREATE INDEX` trên cột con → comment blocking. Lock khi xóa cha: [concurrency.md](concurrency.md). Untrusted FK SS (§11) còn làm optimizer **không** tin FK dù index có.

## 6. CHECK & NULL pass

### 6.0 Hình dung: bảo vệ chỉ đuổi khi chắc chắn SAI

`CHECK` không phải `WHERE`. `WHERE` loại `UNKNOWN`. `CHECK` chỉ **từ chối `FALSE`**. `UNKNOWN` (vì NULL) = “chưa chứng minh sai” → **cho qua**.

Hình dung bảo vệ cửa: chỉ chặn người *rõ ràng* không đủ tuổi. Người không mang giấy (NULL) được vào — trừ khi rule viết `tuổi IS NOT NULL AND tuổi >= 18`.

```text
CHECK (total >= 0)
  total = 10   → TRUE    → vào
  total = -1   → FALSE   → đuổi
  total = NULL → UNKNOWN → vào   ← hay bị hiểu nhầm là “CHECK hỏng”
```

`CHECK (status IN ('new','paid'))` với `status` NULL → `IN` ra UNKNOWN → insert được. Muốn cấm: `NOT NULL` trên cột, hoặc `CHECK (status IS NOT NULL AND status IN (…))`.

`CHECK` fail khi predicate = **FALSE**. `UNKNOWN` (NULL) **qua** — SQL chuẩn.

```sql
ALTER TABLE orders ADD CONSTRAINT chk_total CHECK (total >= 0);

CHECK (status IN ('new', 'paid'))
-- status NULL: IN → UNKNOWN → insert được

CHECK (status IS NOT NULL AND status IN ('new', 'paid'))
-- hoặc cột status NOT NULL + CHECK IN
```

Không subquery (cả hai, CHECK không thấy bảng khác). Cross-table: trigger / `CONSTRAINT TRIGGER` (PG) / indexed view + unique (SS, hạn chế).

SQL Server: CHECK không gọi UDF không deterministic tùy phiên bản — giữ biểu thức đơn. PG: `CHECK` không volatile; `now()` trong CHECK = bất ngờ.

PostgreSQL **19:** `ALTER TABLE … ALTER CONSTRAINT … [NOT] ENFORCED` cho **CHECK** (trước 19: ENFORCED chủ yếu FK). `NOT ENFORCED` ≠ xóa constraint — catalog còn, không kiểm hàng mới. Khác `NOT VALID`. Mục 12.

**Ghi chú:** `CHECK (qty > 0 OR qty IS NULL)` thừa nếu NULL đã qua. Review `CHECK (a < b)` khi `a`/`b` nullable: hàng `a` NULL vẫn vào.

## 7. NOT NULL & DEFAULT

```sql
-- PostgreSQL
ALTER TABLE orders ALTER COLUMN note SET NOT NULL;     -- scan hàng cũ
ALTER TABLE orders ALTER COLUMN status SET DEFAULT 'new';
ALTER TABLE orders ALTER COLUMN status DROP DEFAULT;

-- SQL Server
ALTER TABLE dbo.Orders ALTER COLUMN Note nvarchar(200) NOT NULL;
ALTER TABLE dbo.Orders ADD CONSTRAINT DF_Orders_Status DEFAULT (N'new') FOR Status;
```

Thêm cột `NOT NULL` + default constant: engine hiện đại thường metadata-only (không rewrite hết hàng) trong nhiều trường hợp — vẫn test bảng lớn. `NOT NULL` không default trên bảng có hàng = fail.

`IDENTITY` / `GENERATED … AS IDENTITY` là default đặc biệt, không phải CHECK. Unique trên identity không thay PK.

Domain PG: `CREATE DOMAIN … AS int CHECK (VALUE > 0)` — NOT NULL trên domain ≠ cột.

**Ghi chú:** Default chỉ lúc `INSERT` thiếu cột, không backfill hàng cũ trừ `ADD COLUMN … DEFAULT` (tùy phiên bản lưu default catalog vs viết hàng). Trigger `INSTEAD OF` có thể bỏ default.

## 8. EXCLUDE (PostgreSQL)

`EXCLUDE` = “không thỏa toán tử” trên tập hàng — mạnh hơn UNIQUE (`=`). Thường GiST + range overlap `&&`.

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;   -- khi trộn = btree với GiST

CREATE TABLE room_booking (
    id      int PRIMARY KEY,
    room_id int NOT NULL,
    during  tstzrange NOT NULL,
    EXCLUDE USING gist (room_id WITH =, during WITH &&)
);
```

Hai booking cùng `room_id` với `during` chồng → lỗi. Khác phòng, hoặc khoảng rời, được.

```text
room=1  [10:00, 11:00)  OK
room=1  [11:00, 12:00)  OK  (không chồng, bound phải mở/đóng theo range)
room=1  [10:30, 11:30)  FAIL &&
room=2  [10:00, 11:00)  OK
```

Cần `btree_gist` nếu trộn equality btree với GiST (thường rồi). **Không** dùng `btree_gist` trên `inet`/`cidr` khi nâng 19 — [indexes.md](indexes.md) §12. `int`/`uuid` + range vẫn là pattern chuẩn.

SQL Server **không** có `EXCLUDE`: unique + trigger / app serializable — race nếu chỉ app. Indexed view unique không mô overlap range.

`EXCLUDE` dùng row lock / GiST như unique. Isolation RC vẫn chặn chồng lúc ghi (unique-like). Không thay `WITHOUT OVERLAPS` trên PK temporal (mục 9) — hai surface, đôi khi cùng ý (period vs `tstzrange`).

Partial `EXCLUDE … WHERE (active)`: chỉ hàng thỏa predicate — giống unique partial.

**Ghi chú:** `ACCESS EXCLUSIVE` khi `ALTER` thêm EXCLUDE quét + build index. Production: tạo index GiST trước / thấp điểm. Deadlock hai session chèn khoảng chồng = unique-like, retry `40001`/`40P01` tùy isolation — [concurrency.md](concurrency.md).

## 9. Temporal WITHOUT OVERLAPS & leftover

### 9.0 Hình dung: sửa *một khúc* lịch sử, không sửa cả hàng

Bảng thường: một SKU một hàng — `UPDATE` đổi cả dòng. Bảng application-time: một SKU là **đoạn trên trục thời gian**. `FOR PORTION OF` = “chỉ khúc giữa năm 2026”. Engine **cắt bánh**: khúc giữa lấy giá mới; hai đầu bánh (leftover) là hàng **mới** giữ giá cũ. Không phải “sửa cell rồi xong”.

Vì leftover là `INSERT`, trigger insert chạy, `WITHOUT OVERLAPS` kiểm leftover với hàng *khác*. Race RC: hai session cắt cùng bánh — leftover có thể mất; `SELECT FOR UPDATE` cùng predicate trước. Chi tiết DML: [dml.md](dml.md).

Application-time (SQL:2011): period trên hàng, **không** chồng cho cùng thực thể.

```sql
-- PostgreSQL 18+
CREATE TABLE product_price (
    sku      text NOT NULL,
    price    numeric(12,2) NOT NULL,
    valid_at daterange NOT NULL,
    PRIMARY KEY (sku, valid_at WITHOUT OVERLAPS)
);
```

Cùng `sku` không hai khoảng `valid_at` overlap. PG **19** `UPDATE`/`DELETE FOR PORTION OF` cắt range, insert leftover, **tôn trọng** constraint này.

### 9.1 Leftover — hình

Hàng một khoảng `[2025-01-01, 2027-01-01)`, `price = 80`. Cập nhật portion `[2026-01-01, 2026-07-01)` → `99`:

```text
Trước:
  [2025-01-01                    2027-01-01)  price=80

UPDATE FOR PORTION OF valid_at FROM DATE '2026-01-01' TO DATE '2026-07-01'
SET price = 99

Sau (0–2 leftover với range):
  [2025-01-01, 2026-01-01)  80     ← leftover trái (INSERT)
  [2026-01-01, 2026-07-01)  99     ← phần cắt (UPDATE tại chỗ / thay range)
  [2026-07-01, 2027-01-01)  80     ← leftover phải (INSERT)

Multirange: 0–1 leftover (docs 19). Bound portion = hằng (now() được; không column ref).
```

Leftover = **INSERT thật** — trigger `INSERT` có thể fire; identity/sequence tăng; `RETURNING` không chỉ một hàng. `WITHOUT OVERLAPS` fail nếu leftover chồng hàng *khác* (ví dụ đã có giá `[2026-07-01, 2028-01-01)`).

Hàm `range_minus_multi` / `multirange_minus_multi` (19) mô phép trừ khoảng — đối chiếu docs, đừng bịa signature trong app.

Cú pháp DML: [dml.md](dml.md) §8. Bound **hằng**. `COPY`/`TRUNCATE` không hiểu portion.

### 9.2 Race READ COMMITTED

Hai txn cắt cùng hàng → leftover/lost portion (documented). **`SELECT FOR UPDATE` cùng predicate + portion trước**. RR/SSI: khóa đó không bắt buộc theo docs nhưng test; abort `40001` rồi retry cả khối.

```sql
BEGIN;
SELECT * FROM product_price
WHERE sku = 'ABC'
FOR UPDATE;

UPDATE product_price
FOR PORTION OF valid_at FROM DATE '2026-01-01' TO DATE '2026-07-01'
SET price = 99
WHERE sku = 'ABC';
COMMIT;
```

SQL Server: `PERIOD FOR SYSTEM_TIME` + `SYSTEM_VERSIONING` = **system-time** (history tự động), không `WITHOUT OVERLAPS`, không `FOR PORTION OF`. Application-time trên SS: cột từ/đến + trigger / indexed view.

**Ghi chú:** **Beta** 19. Đừng map `FOR SYSTEM_TIME` sang `valid_at`. Không dùng cho bitemporal đầy đủ trừ khi tự quản system-time. Không bịa `FOR PORTION OF SYSTEM_TIME`.

## 10. Deferred (PostgreSQL)

```sql
CREATE TABLE a (
    id int PRIMARY KEY,
    b_id int
);
CREATE TABLE b (
    id int PRIMARY KEY,
    a_id int REFERENCES a (id)
);
ALTER TABLE a
    ADD CONSTRAINT a_b_fk
    FOREIGN KEY (b_id) REFERENCES b (id)
    DEFERRABLE INITIALLY DEFERRED;

BEGIN;
INSERT INTO a (id, b_id) VALUES (1, 1);   -- b chưa có; OK nếu deferred
INSERT INTO b (id, a_id) VALUES (1, 1);
COMMIT;                                   -- kiểm lúc COMMIT
```

`DEFERRABLE INITIALLY IMMEDIATE` + `SET CONSTRAINTS … DEFERRED` trong txn. `NOT DEFERRABLE` (mặc định): không trì hoãn.

SQL Server: **không** defer FK. Insert vòng: disable / staging / thứ tự / trigger.

Unique/PK/CHECK cũng defer được nếu khai báo `DEFERRABLE` (PG). Unique deferred = đến COMMIT mới lỗi trùng — khó debug.

**Ghi chú:** `SET CONSTRAINTS ALL DEFERRED` không biến FK `NOT DEFERRABLE` thành deferred. ORM “flush vòng” cần schema `DEFERRABLE`. `postgres_fdw` **19** thừa `READ ONLY`/`DEFERRABLE` sang remote — txn read-only không ghi remote — [transactions.md](transactions.md) §12.

## 11. NOCHECK & FK untrusted

SQL Server phân **disabled** vs **untrusted** — hay nhầm.

```sql
-- Tắt kiểm (hàng mới cũng không check FK đó)  → is_disabled = 1
ALTER TABLE dbo.Orders NOCHECK CONSTRAINT FK_Orders_Customers;

-- Bật lại NHƯNG không quét hàng cũ → is_not_trusted = 1, is_disabled = 0
ALTER TABLE dbo.Orders CHECK CONSTRAINT FK_Orders_Customers;

-- Bật lại VÀ quét — mới trusted
ALTER TABLE dbo.Orders WITH CHECK CHECK CONSTRAINT FK_Orders_Customers;
```

`WITH NOCHECK ADD CONSTRAINT` lúc tạo: không quét data cũ; constraint **untrusted**. Optimizer **không** dùng FK cho join elimination / infer NOT NULL phía con.

```sql
SELECT name, is_disabled, is_not_trusted
FROM sys.foreign_keys
WHERE parent_object_id = OBJECT_ID(N'dbo.Orders');
```

| Trạng thái | Hàng mới | Hàng cũ | Optimizer tin FK |
|---|---|---|---|
| Trusted (`WITH CHECK`) | Kiểm | Đã quét | Có |
| Untrusted, enabled | Kiểm | Có thể mồ côi | **Không** |
| Disabled (`NOCHECK`) | Không | Có thể mồ côi | Không |

Untrusted + `is_disabled = 0`: hàng *mới* vẫn bị check, hàng *của ETL đêm* có thể mồ côi. Plan join elimination biến mất → CPU tăng *im lặng*, không lỗi constraint.

```sql
-- ETL đúng
ALTER TABLE dbo.Orders NOCHECK CONSTRAINT FK_Orders_Customers;
-- load
ALTER TABLE dbo.Orders WITH CHECK CHECK CONSTRAINT FK_Orders_Customers;
-- sai: CHECK CONSTRAINT không WITH CHECK → untrusted
```

**Ghi chú:** Luôn `WITH CHECK CHECK CONSTRAINT` khi xong. Không tương đương PG `NOT VALID` (hàng mới luôn kiểm; `convalidated` rõ). Không tương đương `NOT ENFORCED`.

---

## 12. Disable / NOT VALID / ENFORCED

**PostgreSQL `NOT VALID`:** thêm FK/CHECK không quét hàng cũ. Hàng **mới** vẫn kiểm. Validate sau, lock nhẹ hơn add + scan một nhịp:

```sql
ALTER TABLE orders
    ADD CONSTRAINT orders_customer_fk
    FOREIGN KEY (customer_id) REFERENCES customers (id) NOT VALID;

ALTER TABLE orders VALIDATE CONSTRAINT orders_customer_fk;
```

`VALIDATE` lấy `SHARE UPDATE EXCLUSIVE` (không `ACCESS EXCLUSIVE` suốt scan như một số `ALTER` khác) — vẫn đợi txn dài. Catalog: `pg_constraint.convalidated`.

### 12.1 CHECK `[NOT] ENFORCED` (PG 19)

Docs `ALTER TABLE` 19: enforceability đổi được cho **FOREIGN KEY và CHECK**. Deferrability vẫn chỉ FK.

```sql
ALTER TABLE orders ALTER CONSTRAINT chk_total NOT ENFORCED;
ALTER TABLE orders ALTER CONSTRAINT chk_total ENFORCED;
```

- `NOT ENFORCED`: **không** kiểm hàng mới *và* không quét. Catalog còn — documentation / tối ưu “tin” constraint ở chỗ không ảnh hưởng đúng đắn (docs CREATE TABLE: engine *có thể* vẫn giả định thỏa cho một số quyết định optimizer).
- `ENFORCED` (từ NOT ENFORCED): **scan** hàng cũ (Phase 3) rồi kiểm hàng mới. Partition/inherit: recurse con.

`NOT ENFORCED` ≠ `NOT VALID` (hàng mới vẫn kiểm). ≠ `NOCHECK` SS (disabled) — gần *ý* “tắt kiểm” hơn `NOT VALID`.

Thêm CHECK `NOT ENFORCED`: không verification lúc ADD.

SQL Server không `NOT VALID` / `NOT ENFORCED`. Gần: `WITH NOCHECK ADD` (untrusted, hàng mới check) vs `NOCHECK CONSTRAINT` (tắt hẳn).

Disable unique/PK: drop index/constraint — không “tắt unique” nhẹ như FK.

**Ghi chú:** `NOT VALID` + quên `VALIDATE` = mồ côi tồn tại mãi, hàng mới sạch. `NOT ENFORCED` quên bật lại = invariant chết trên hàng mới. Monitor `convalidated` / `conenforced` (catalog 19 — đối chiếu `pg_constraint`, đừng bịa cột nếu beta đổi tên: đọc `\d pg_constraint`).

## 13. Worked examples

### 13.1 FK + index + NOT VALID

```sql
BEGIN;
ALTER TABLE orders
    ADD CONSTRAINT orders_customer_fk
    FOREIGN KEY (customer_id) REFERENCES customers (id)
    ON DELETE RESTRICT
    NOT VALID;
CREATE INDEX ix_orders_customer ON orders (customer_id);
COMMIT;
-- thấp điểm
ALTER TABLE orders VALIDATE CONSTRAINT orders_customer_fk;
```

SQL Server: `WITH CHECK ADD` lúc thấp điểm; luôn `CREATE INDEX` trên `CustomerId`. Sau ETL: `WITH CHECK CHECK CONSTRAINT`.

### 13.2 Unique NULL nghiệp vụ

```sql
-- PG: tối đa một NULL
ALTER TABLE users ADD CONSTRAINT uq_phone UNIQUE NULLS NOT DISTINCT (phone);

-- SS: bắt NOT NULL hoặc sentinel; filtered không đủ
ALTER TABLE dbo.Users ALTER COLUMN Phone nvarchar(32) NOT NULL;
CREATE UNIQUE INDEX ux_users_phone ON dbo.Users (Phone);
```

### 13.3 Phòng họp không chồng

```sql
-- PostgreSQL
EXCLUDE USING gist (room_id WITH =, during WITH &&)

-- SQL Server: không EXCLUDE — serializable + unique (room, start) không đủ overlap
-- Dùng logic app + UPDLOCK hoặc bảng slot rời
```

### 13.4 Leftover vs WITHOUT OVERLAPS

```text
Đã có sku ABC:
  [2026-01-01, 2026-12-31)  price 10
  [2027-01-01, 2028-01-01)  price 12

UPDATE portion [2026-06-01, 2027-06-01)  -- leftover phải chồng hàng 2027
  → FAIL WITHOUT OVERLAPS
Sửa: cắt portion nằm trong một hàng, hoặc xóa/chỉnh hàng kề trước
```

### 13.5 Untrusted vs NOT VALID vs NOT ENFORCED

```text
Cần thêm FK trên bảng 50M, giờ cao điểm
  PG: ADD NOT VALID (hàng mới sạch) → VALIDATE đêm
  SS: WITH NOCHECK ADD (untrusted, hàng mới sạch) → WITH CHECK CHECK đêm
      quên WITH CHECK = plan xấu mãi

Cần tắt CHECK nặng tạm
  PG 19: ALTER CONSTRAINT … NOT ENFORCED  (hàng mới cũng lọt)
  SS: NOCHECK CONSTRAINT
  Không dùng NOT VALID cho “tắt”
```

### 13.6 Chuỗi CASCADE

```text
customers ──CASCADE──► orders ──CASCADE──► order_lines
DELETE customer 1  →  xóa N order  →  xóa M lines
Lock + log + (PG) dead tuple hàng loạt
RESTRICT trên orders ← customers: xóa khách fail nếu còn đơn — thường đúng nghiệp vụ
```

Đo `DELETE` cha trên staging đủ dữ liệu. Trigger `INSTEAD OF DELETE` không thay FK. Soft-delete: FK vẫn thấy hàng cha “xóa” — `deleted_at` không tắt FK.

### 13.7 EXCLUDE vs UNIQUE vs WITHOUT OVERLAPS

| Invariant | Công cụ | Engine |
|---|---|---|
| `=` trên cột | `UNIQUE` / PK | cả hai |
| `=` kể cả NULL | `NULLS NOT DISTINCT` | PG 15+ |
| `&&` range + `=` cột | `EXCLUDE gist` | PG |
| Period không chồng cùng key | `WITHOUT OVERLAPS` | PG 18+ |
| Overlap ngày trên SS | trigger / indexed view / app + `UPDLOCK` | SS |

`WITHOUT OVERLAPS` trên PK/UNIQUE dùng rangetype period — leftover `FOR PORTION OF` phải thỏa cùng constraint. `EXCLUDE` trên `tstzrange` không tự cắt leftover — DML thường `UPDATE` cả hàng.

Race RC hai `INSERT` khoảng chồng: GiST/unique lock — một fail unique-like, không “cả hai lọt” nếu constraint engine (khác app check).

### 13.8 Untrusted phá join elimination

```sql
-- Optimizer SS có thể bỏ join customers nếu FK trusted
-- is_not_trusted = 1 → plan giữ join, CPU tăng, không lỗi
SELECT o.Id, o.CustomerId
FROM dbo.Orders AS o
WHERE EXISTS (SELECT 1 FROM dbo.Customers AS c WHERE c.Id = o.CustomerId);
```

Review PR ETL: bắt `WITH CHECK CHECK CONSTRAINT` trong script, không chỉ `CHECK CONSTRAINT`. Catalog `is_not_trusted` vào monitoring tuần.

PG `convalidated = false`: planner không giả định mọi hàng có cha — tương tự *ý*, catalog khác.

### 13.9 Circular insert

```sql
-- PG deferred
BEGIN;
INSERT INTO a (id, b_id) VALUES (1, 1);
INSERT INTO b (id, a_id) VALUES (1, 1);
COMMIT;

-- SS: không defer
-- 1) insert a với b_id NULL, insert b, update a
-- 2) NOCHECK tạm — quên WITH CHECK = untrusted
-- 3) staging table rồi MERGE thứ tự
```

`DEFERRABLE` unique: trùng đến COMMIT mới lỗi — log app “insert OK” rồi fail lúc commit. Khó hơn unique immediate.

## 14. Best practices & checklist

- Invariant trong constraint, không chỉ app. Race cần unique/EXCLUDE + isolation phù hợp.
- Mỗi FK: index cột con. `ON DELETE CASCADE` chỉ khi nghiệp vụ xóa cây.
- CHECK: nhớ NULL pass; `NOT NULL` + IN list rõ ràng.
- Unique + NULL: nói rõ `NULLS NOT DISTINCT` vs filtered.
- PG: `NOT VALID` + `VALIDATE`; không `NOCHECK` kiểu SS.
- SS: sau ETL `WITH CHECK CHECK CONSTRAINT`; soi `is_not_trusted`.
- Temporal: `WITHOUT OVERLAPS` + `FOR UPDATE` trước `FOR PORTION OF` ở RC; leftover = INSERT.
- Deferred chỉ khi insert vòng; unique deferred khó vận hành.
- Đổi PK = dự án riêng (rewrite, FK, downtime).
- PG 19: `NOT ENFORCED` CHECK nhớ bật lại; `ENFORCED` = scan.

## 15. Bẫy khi review

- FK không index — `DELETE` cha scan bảng con.
- `ON DELETE CASCADE` trên `customers` → mất `orders`.
- `CHECK (status IN (…))` cột nullable, app tin “luôn new|paid”.
- Unique “một NULL” trên SS bằng filtered index.
- `NOCHECK` rồi `CHECK` không `WITH CHECK` — untrusted, mất join elimination.
- Nhầm `NOT VALID` = `NOCHECK` (hàng mới / trusted khác nhau).
- Nhầm `NOT ENFORCED` = `NOT VALID`.
- Port `EXCLUDE` / `WITHOUT OVERLAPS` sang SS bằng unique hai cột thời điểm.
- `BEGIN` T-SQL + `SET CONSTRAINTS` (không tồn tại).
- CHECK subquery “thấy bảng khác” — không portable, thường illegal.
- `NOT ENFORCED` (PG 19) quên bật lại trước GA prod.
- App unique check `SELECT` rồi `INSERT` không khóa — [concurrency.md](concurrency.md).
- `FOR PORTION OF` ở RC không `FOR UPDATE`; leftover chồng hàng kề.
- Trigger INSERT trên leftover làm nghiệp vụ “cập nhật giá” gửi mail hai lần.
- `btree_gist` inet trên EXCLUDE — upgrade 19 chặn (khác room_id int).

## Phụ lục A. Unique vs PK vs indexed view / EXCLUDE

| Invariant | Công cụ |
|---|---|
| Một hàng định danh | `PRIMARY KEY` |
| Không trùng nghiệp vụ, nhiều NULL OK | `UNIQUE` mặc định |
| Không trùng kể cả NULL | PG `NULLS NOT DISTINCT`; SS thiết kế `NOT NULL` |
| Không chồng range | PG `EXCLUDE` / `WITHOUT OVERLAPS` |
| Biểu thức / join | SS indexed view `UNIQUE`; PG unique expression index |

Indexed view SQL Server: `SCHEMABINDING`, `SET` options, Enterprise/query hint `NOEXPAND` trên Standard historically — kiểm edition 2025. Không thay FK.

---

## Phụ lục B. Trigger không phải constraint

`CREATE TRIGGER` chạy sau/trước DML, có thể `RAISERROR`/`RAISE`. Bulk/`COPY`/`TABLOCK`/`DISABLE TRIGGER` / `session_replication_role` (PG) / `IDENTITY_INSERT` không cùng đường. Constraint unique/FK engine **không** tắt vì replication role trừ replica identity / `DISABLE`. Review “constraint trong trigger” = race + bypass.

Constraint trigger PG (`CONSTRAINT TRIGGER`) defer được như FK — vẫn không thấy bảng khác trong CHECK.

Leftover temporal fire trigger INSERT: test trước khi bật mail/audit “mỗi UPDATE giá”.

## Phụ lục C. Catalog khi review PR

```sql
-- SQL Server: FK untrusted / disabled
SELECT name, is_disabled, is_not_trusted, delete_referential_action_desc
FROM sys.foreign_keys;

-- PostgreSQL: validated / defer / enforced
SELECT conname, contype, convalidated, condeferrable, condeferred
FROM pg_constraint
WHERE conrelid = 'orders'::regclass;
-- 19: cột enforce — \d pg_constraint (conenforced / tương đương docs)
```

`contype`: `p` PK, `u` unique, `f` FK, `c` check, `x` exclude. Thiếu index FK: so cột `confrelid` với `pg_index`. SS: `sys.foreign_key_columns` vs `sys.index_columns`.

## Phụ lục D. Leftover 0–2 — bảng

Hàng range `[L, R)`, portion `[P, Q)` (P, Q hằng; `L < R`).

| Quan hệ | Leftover |
|---|---|
| `[P,Q)` nằm hẳn ngoài `[L,R)` | 0 hàng đổi (predicate không khớp) |
| `[P,Q)` phủ hết `[L,R)` | 0 leftover; UPDATE/DELETE cả hàng |
| Cắt giữa (`L < P < Q < R`) | 2 leftover (trái `[L,P)`, phải `[Q,R)`) |
| Cắt một đầu | 1 leftover |
| Multirange | 0–1 leftover (docs 19) |

Trigger: mỗi leftover = `INSERT`. `IDENTITY` lỗ. `WITHOUT OVERLAPS` fail nếu leftover chồng hàng kề — không phải “engine sai”, là dữ liệu period đã khít.

Race RC không `FOR UPDATE`: session A cắt, session B cắt khác portion cùng hàng → leftover mất/chồng (documented). Retry cả txn.

## Phụ lục E. `NOT ENFORCED` vs optimizer

Docs CREATE TABLE 19: `NOT ENFORCED` = app chịu invariant; engine **có thể** vẫn giả định thỏa cho một số quyết định optimizer *không ảnh hưởng đúng kết quả*. Đừng tắt CHECK rồi dựa “optimizer không tin” như SS untrusted. SS untrusted = **không** join elimination. Hai mô hình khác — test plan.

Bật lại `ENFORCED`: scan hàng cũ (fail nếu bẩn). Partition: recurse con kể khi parent đã NOT ENFORCED.

## Phụ lục F. NULLS NOT DISTINCT — composite

```sql
-- PG 15+
CREATE TABLE t (
    tenant int,
    phone  text,
    UNIQUE NULLS NOT DISTINCT (tenant, phone)
);
-- (1, NULL) trùng (1, NULL) → lỗi
-- (1, NULL) và (2, NULL) → được (tenant khác)

-- Mặc định NULLS DISTINCT
-- (1, NULL) và (1, NULL) → được
```

SS filtered `WHERE phone IS NOT NULL`: hai `(1, NULL)` lọt. Port “optional phone unique per tenant” từ PG sang SS = `NOT NULL` hoặc sentinel `''` (rồi unique) — không filtered.

Unique filtered `WHERE deleted_at IS NULL`: nhiều hàng xóa mềm cùng phone — được; hai active trùng — lỗi. Khác `NULLS NOT DISTINCT`.

## Phụ lục G. CHECK NULL — bảng chân trị

```text
CHECK (total >= 0)
  total = 0     TRUE  → qua
  total = -1    FALSE → fail
  total NULL    UNKNOWN → qua

CHECK (status IN ('a','b'))
  status NULL → qua  (app tưởng “luôn a|b”)

Sửa: status NOT NULL + CHECK IN
  hoặc CHECK (status IS NOT NULL AND status IN ('a','b'))
```

PG 19 `NOT ENFORCED` trên CHECK: hàng mới cũng lọt — không dùng để “sửa data rồi quên bật”. `NOT VALID`: hàng mới vẫn kiểm.

SS CHECK UDF không deterministic: tránh. PG `now()` trong CHECK = bất ngờ theo thời điểm ghi.

Leftover `FOR PORTION OF` = INSERT: đếm trigger, identity, `WITHOUT OVERLAPS` hàng kề. Untrusted SS: `WITH CHECK CHECK CONSTRAINT` sau ETL — `is_not_trusted` vào alert. `NOT VALID` ≠ `NOT ENFORCED` ≠ `NOCHECK`.

EXCLUDE gist `(room_id WITH =, during WITH &&)` + `btree_gist` cho int — **không** inet/cidr lúc nâng 19. FK luôn index cột con. Deferred chỉ vòng insert; unique deferred khó debug. CHECK 19 ENFORCED scan khi bật lại.

MATCH SIMPLE: một cột FK NULL = không đòi cha. `MATCH FULL` (PG): một NULL + một non-null = lỗi. SS không MATCH FULL. Circular insert: PG `DEFERRABLE`; SS thứ tự / NULL rồi UPDATE / (tránh) `NOCHECK` quên `WITH CHECK`.

Leftover range: cắt giữa → 2 INSERT; phủ hết → 0 leftover; race RC → `FOR UPDATE`. Catalog SS `is_not_trusted`; PG `convalidated`. CHECK `[NOT] ENFORCED` **19**.

## Phụ lục H. Checklist constraint (WHY)

1. **ETL SS: `WITH CHECK CHECK CONSTRAINT`** — quên = untrusted, mất join elimination.
2. **PG: `NOT VALID` rồi `VALIDATE`** — hàng mới sạch; khác `NOT ENFORCED`.
3. **CHECK 19 `ENFORCED` = scan** — bật lại trên bảng bẩn sẽ fail.
4. **`FOR PORTION OF` + `FOR UPDATE` ở RC** — leftover INSERT; `WITHOUT OVERLAPS`.
5. **`NULLS NOT DISTINCT` không = filtered unique SS**.
6. **EXCLUDE gist int+range OK; inet/cidr `btree_gist` chặn 19**.
7. **Mỗi FK một index cột con**.
8. **Không `ON DELETE CASCADE` trên `customers` trừ khi nghiệp vụ xóa cây**.
